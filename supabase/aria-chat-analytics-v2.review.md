# Aria v2 — no-schema-change release adapter
The additive SQL proposal remains a review artifact only, not deployed. The existing `website-landing-event` collector stores a validated, versioned envelope in the existing `event_source` column for the dedicated `aria_chat_event` type. No new DB column, index, RPC, historical rewrite, or production data migration. Normal tracking and form transport remain unchanged. The native authenticated staff report already returns date/source aggregates; the admin groups these by anonymous visit/chat/sequence, deduplicating repeat delivery by sequence. A genuine repeated question has a new sequence. No typed text or contact values are stored in this envelope. QA mode is explicit and separately rendered. Report covers observed events in the selected date interval, not full-lifetime cohorts across boundaries; missing sequence/open counts indicate partial observations. Confirmed success means response accepted by existing form backend, not an independent CRM join. Exact inactivity duration not available in date aggregates. Existing data retention unchanged; set a reviewed retention policy before long-term scaling. Rollback: revert web/admin PRs, restore previous collector source; leave valid telemetry intact. No changes to CAPI, web-form-submit, CRM, customer app or database schema.
