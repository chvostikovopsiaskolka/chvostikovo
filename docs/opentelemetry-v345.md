## Privacy and access

Only app/build, predefined technical category/operation/surface, browser family/major version, platform, whitelisted exception type, own code-file name/line/column, HTTP status, bounded duration and random trace/span IDs are retained. No message text, exception message, raw stack, full URL/query/fragment, request/response body, headers, password/token, form field, account/dog name/ID, photo, cookie, full user agent, IP address or session replay is stored in diagnostics. Existing platform access/auth logs are separate and are not changed by this feature. Transport still uses the app's normal authenticated Supabase header, never stores that token in a trace.

A custom exporter serializes whitelisted fields into OTLP JSON and sends it to portal_telemetry_ingest_v345 through the existing authenticated Supabase REST RPC transport. It is not a general-purpose public OTLP collector endpoint. The server authenticates a live auth.sessions session and active/unblocked customer or staff, prevents customer app='admin' spoofing, validates payload shape/size/batch, revalidates every retained field, and discards arbitrary OTLP fields. A private table stores flattened columns, never raw payload. Unique trace/span IDs deduplicate retries. Anonymous and customer direct reads are denied; portal_staff_telemetry_v345 is active-staff/session-only and returns bounded seven-day aggregates (max100groups). All new function grants are explicit; private tables have RLS and no anon/authenticated direct grants.

Per-user daily-salted hashes are retained only in a private rate-limit table for one day, without raw user ID/IP;60spans/10minutes/user and5000spans/day globally. Events are removed after30days by an hourly pg_cron cleanup; stale budgets are also deleted. No new provider receives customer diagnostics. No marketing/AI-traffic statistics or business records are changed. The code-level whitelist and database permissions must stay authoritative in future instrumentation. Do not add recordException(error), console recording, URL/query capture, form capture or SDK auto-instrumentation without a new privacy review.

## Admin and troubleshooting

Menu → Technický stav appiek opens a native responsive modal with app/build, operation, count, browser/type, source line, status/duration and latest Europe/Bratislava time. It loads on open/explicit refresh, shows unavailable on failure, and supports close/Escape/focus/sign-out cleanup. No periodic report polling. Requested automatic staff notifications use the existing portal_notifications/admin-push path with app_diagnostics_admin, routed exclusively to admin subscriptions. Three matching severe events in15minutes trigger one generic summary; a locked global config row enforces at most one/hour and a private fingerprint ledger silences the same build/problem for24hours. Expected4xx and slow requests below30seconds never alert. Alerts go only to active staff; no exception/body/person data is included. Diagnostic-alert problems cannot affect app business requests. The reporter does not cancel a pending reservation/message request: a30second watchdog records an unfinished request and a separate visible/online startup watchdog records an unhidden loading layer. A completely unexecuted page, offline device or lost telemetry cannot reliably report itself. No full server trace or source-code/session replay viewer is implied.

During a requested investigation, an assistant with the authorized Supabase connection can inspect the same private aggregate or SQL records. There is no always-running AI agent and no automatic code modification/deployment. Runtime errors require reproduction, diagnosis, appropriate tests and a normal guarded release.

Emergency stop: update private.app_telemetry_config_v345 set enabled=false where singleton; this stops server storage while app behavior continues. Client-side ChvoTelemetry.disable() stops local recording/export for that page. To undo the release, revert the customer instrumentation/build/cache coherently against the current branch and restore the exact admin backup only if the current live hash is the v345 candidate; disable ingestion first. New telemetry tables may be retained for investigation or removed only with explicit data-deletion intent.
