# v358 — optional five-step guide and notice photo loading

New customers are offered **Sprievodca appkou** only after the existing onboarding completes and all assigned dogs meet the current vaccination gate. Existing profiles are excluded by the database migration; one verified owner account may be explicitly enabled for acceptance testing. Skip opens no fallback summary. Settings contains a replay action for every account.

The five steps cover the dog overview, passes and visits, the orange reservation button, reservations/taxi, and Menu. Empty bookings use a clearly labelled DOM-only example which never enters application data, capacity, payments, reservations or notifications. Continue, Back, Skip/Escape and completion restore navigation and remove the example. The fixed navigation and existing vaccination/booking rules are unchanged.

`intro_guide_eligible` is added with false for existing profiles, then a true default for future profiles. Seen time/result are saved via `portal_record_guide_v358` with SECURITY INVOKER, own-profile RLS and column-level UPDATE grants for only these two fields. No extra bootstrap read or Edge deployment: the current API returns the full own profile. The browser remembers a pending result per account and retries on a subsequent ordinary bootstrap if needed. A completed result cannot be downgraded by the RPC. No new polling.

Current notice photos (at most two) preload into a bounded eight-image cache. Opening a notice with a photo shows a cancellable loading state until the image is decoded, then reveals article and image together. A seven-second/image-error fallback preserves the text with a retry explanation. Epoch/account checks prevent delayed images reopening a closed article or another account's view. Main article previews use at most 32svh; the separate full-screen viewer and pinch zoom remain unchanged.

Validation: actual customer runtime for one/two dogs, existing-account/unfinished-onboarding/invalid-vaccine gates, skip and replay, five-step progression, unchanged operational data, photo decode/cache/close races and zoom; SQL defaults/RLS/anon/invalid input and completion ordering; production own-role SQL tests in ROLLBACK. Chromium 320/360/390/430/844×390/1280 for one/two dogs, five visible spotlights, contained cards, stable navigation and demo cleanup. Existing customer design and v357 session regression tests pass. Physical signed-in iOS and Android remain unobserved.

Baseline: production commit `82e3d1ec8d54f289df7ea6bf3f74ecb2bd8088f7`, Vercel `dpl_rWCJ5d1EUnedcNM7NL2uu1vj1WBY`, immutable branch `backup/customer-before-guide-v358-20261023`.

Do not drop columns after newer code starts using them. No customer messages, SMS, push or Meta conversions are sent by the guide.
